# 06. 문제해결

## 시작 파일이 열리지 않는다

- Windows: Python을 다시 설치하면서 `Add python.exe to PATH`를 체크하고 [08_Windows_설치](08_Windows_설치.md)를 확인합니다.
- macOS: 패키지 루트의 `시작하기.command`를 우클릭해 열거나 터미널에서 `bash 시작하기.command`를 실행합니다. 기존 `00_시작/시작하기.command`도 계속 사용할 수 있습니다.
- 패키지를 옮긴 뒤 환경이 준비되지 않았다고 나오면 시작 파일을 다시 실행합니다. 자동 환경 준비가 실패하면 `python3 00_시작/launch.py`의 CLI 메뉴에서 `[1] 환경 점검·설치`를 실행합니다.

## 사진 업로드가 거부된다

- 지원 확장자는 JPG, JPEG, PNG, HEIC, HEIF, TIF, TIFF, BMP, WEBP입니다.
- 파일명에서 `#`, `?`, `%`, `/`, `\`와 제어문자를 제거합니다.
- Windows 예약 이름(`CON`, `PRN`, `AUX`, `NUL`, `COM1`~`COM9`, `LPT1`~`LPT9`)과 끝의 공백·점은 사용할 수 없습니다.
- 폴더를 끌어놓지 말고 시작 화면의 `폴더 열기`로 원본 폴더를 연 뒤 복사합니다.

화면 아래의 파일별 실패 사유를 확인하면 어느 규칙에 걸렸는지 알 수 있습니다. 같은 이름의 다른 사진은 기존 원본을 덮지 않고 `_2`, `_3` 이름으로 저장됩니다.

## 사진이 목록에 없다

1. 원본이 `01_원본사진`에 있는지 확인합니다.
2. 헤더 `② 준비`에서 `사진 준비`를 다시 실행합니다.
3. 축소본이 `02_작업장/<발표>/img`에 있는지 확인합니다.
4. 명령으로 준비했다면 목록을 다시 만듭니다.

```bash
python3 02_작업장/slide_tool/gen_manifest.py
```

지원되는 목록 확장자는 JPG, JPEG, PNG입니다. HEIC·HEIF 원본은 사진 준비 단계에서 JPG 축소본으로 변환됩니다. 이름의 `#`, `?`, `%`도 제거하세요.

## 준비 뒤에 사진을 넣었더니 화면 위에 띠가 뜬다

"원본이 바뀌었습니다(새 사진 N장)" 띠입니다. 준비 당시와 원본 폴더가 달라졌다는 뜻입니다. 지금 작업을 보관하고 새로 시작하려면 `새 행사 시작…`, 원본 전체로 발표를 다시 나누려면 `다시 나누기`를 누릅니다([03_사진_넣기](03_사진_넣기.md)). 새 사진이 계획에 없는 채로 `그대로 준비`를 누르면 실패합니다.

## `사진 준비`·`PDF 만들기` 버튼이 눌리지 않는다

버튼이 회색이면 마우스를 올려 이유를 봅니다. 원본 사진이 0장이거나, 이미 다른 작업이 실행 중이거나, 도구 서버가 꺼졌을 때 그렇습니다. 이유대로 사진을 넣거나 작업이 끝나기를 기다리거나 시작 파일을 다시 실행하세요.

## 도구가 열리지 않는다

- 시작 파일을 다시 실행하면 브라우저가 자동으로 열립니다. 이미 열려 있는 탭이 서버가 꺼진 옛 탭이면 닫고 새로 열린 탭을 씁니다.
- 열린 주소가 `http://127.0.0.1:<포트>/slide_tool/`인지 확인합니다. `file://` 주소로 열지 않습니다.
- 포트가 사용 중이면 기존 도구 창과 서버를 종료한 뒤 다시 시작합니다. 포트가 바뀌면 브라우저 저장값이 따로 저장되므로, 화면 위 띠의 `최근 백업 불러오기`를 쓰거나 먼저 백업하세요.

## "도구 서버가 꺼졌습니다"가 보인다

시작 파일을 실행한 검은 창을 닫았거나 탭을 닫아 서버가 종료된 상태입니다. 헤더의 `다시 연결`을 눌러 보고, 안 되면 시작 파일을 다시 실행합니다. 이미 맞춘 경계·색은 브라우저에 남아 있어 그대로 이어서 할 수 있지만, 사진 준비·경계 자동 찾기·PDF 만들기는 서버가 켜져 있어야 합니다.

## “보안 확인 실패”가 보인다

- 시작 파일이 연 로컬 주소가 맞는지 확인합니다.
- `file://`, 다른 포트에서 복사한 탭, 외부 페이지 안의 프레임에서는 워크플로 토큰을 받을 수 없습니다.
- 탭을 닫고 시작 파일을 다시 실행합니다. 경계·색 보정은 브라우저 저장값에 남지만, 사진 준비와 고해상도 PDF 기능은 올바른 로컬 서버에서만 켜집니다.

## PDF 생성 중 창을 닫았다

실행 중인 잡은 서버에서 계속 진행합니다. 완료된 뒤 heartbeat가 없으면 서버가 자동 종료됩니다. `03_결과물`을 열어 PDF와 `백업` 사본을 확인하고, 불완전한 파일이 보이면 시작 파일을 다시 열어 PDF를 다시 만듭니다.

## 작업이 사라진 것처럼 보인다

같은 브라우저와 같은 주소(포트)인지 확인합니다. 브라우저 캐시 삭제, 시크릿 창 종료, `localhost`와 `127.0.0.1` 사이 이동, 발표·파일 이름을 폴더에서 직접 바꾼 경우는 저장값을 분리시킵니다. 화면 위에 아래 띠가 나오면 `최근 백업 불러오기`를 누릅니다. PDF를 만든 적이 있으면 `03_결과물/백업/`에 백업이 있습니다.

![백업 불러오기 띠. 이 주소에는 저장된 보정값이 없고 최근 백업을 불러올 수 있다는 안내입니다](img/16_백업불러오기띠.png)

띠가 안 보이면 헤더 `⋯` 메뉴의 `백업 불러오기…`로 직접 받아 둔 백업 JSON을 고릅니다.

## HEIC를 읽지 못한다

환경 점검에서 `pillow-heif`를 설치하거나 다음 명령을 현재 `.venv`에서 실행합니다.

```bash
python3 -m pip install pillow-heif
```

## PDF가 흐리거나 원본을 못 찾는다

- 헤더 `④ PDF`에서 원하는 방식으로 만듭니다. `⋯` 메뉴의 백업 버튼은 PDF가 아니라 작업 상태 JSON용입니다.
- 원본과 축소본의 stem이 같은지 확인합니다.
- 원본이 `01_원본사진` 또는 그 하위 폴더에 있는지 확인합니다.

## PDF에 배경이 그대로 나오거나 쪽이 빠졌다

- 경계를 손대지 않은 사진은 사진 전체가 들어갑니다. 왼쪽 필터의 `미작업`을 눌러 남은 사진의 경계를 맞추거나 `제외`하세요.
- 완료 배너의 "발표별 쪽 수"로 빠진 발표가 없는지 확인합니다. `완료본만`을 체크했다면 완료 표시하지 않은 사진은 빠집니다(발표자료 `자료` 쪽은 항상 들어갑니다).

## 자동 찾기가 엉뚱한 곳을 잡았다

`확인 필요`·`자동` 배지가 붙은 사진은 눈으로 확인하고 손잡이로 고치세요. 옆으로 누운 사진은 `돌려서 다시 찾기`가 도움이 됩니다. 결과 전체가 마음에 들지 않으면 알림의 `되돌리기` 또는 도구줄의 `원래대로`를 누릅니다.

## PDF 색이 화면과 다르다

무아레·어두운 영역 정리는 최종 PDF가 더 정밀할 수 있습니다. 그 밖의 차이는 다음 게이트로 확인합니다.

```bash
python3 05_스크립트/test_color_parity.py
```

실패하면 [07_개발자_노트](07_개발자_노트.md)의 계약을 확인하세요.

## 통합 PDF만 실패한다

poppler의 `pdfunite`가 없거나 실행에 실패했을 수 있습니다. 통합 모드는 시작 전에 이를 확인하며, 실패한 실행의 새 PDF는 결과 폴더에 반영하지 않습니다. poppler를 설치·점검한 뒤 다시 실행하세요.
