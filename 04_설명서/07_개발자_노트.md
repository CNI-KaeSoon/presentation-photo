# 07. 개발자 노트

코드를 수정할 때는 결과가 조용히 달라지는 계약부터 확인합니다.

## 핵심 불변식

1. `02_작업장/slide_tool/index.html`의 `COLOR_CORE`와 `05_스크립트/slide_color.py`는 같은 입력에 같은 픽셀 결과를 내야 합니다.
2. `--workers 1`은 기준 직렬 경로입니다. 병렬 경로의 출력 순서와 바이트 결과가 같아야 합니다.
3. 이미지 저장 키 `../<그룹>/img/<파일>`과 `data.js`의 `file` 값은 그대로 유지합니다.
4. 원본 사진은 읽기 전용입니다.
5. 패키지 내부 경로는 현재 작업 디렉터리가 아니라 `Path(__file__)` 또는 계획 파일 위치를 기준으로 계산합니다.

## 색연산 계약

색 코어를 바꾸면 다음을 함께 검토합니다.

- `02_작업장/slide_tool/index.html`: 슬라이더 정의와 JavaScript 계산
- `05_스크립트/slide_color.py`: 기본값과 Python 계산
- `05_스크립트/test_color_parity.py`: 경계값 회귀 케이스

자동 레벨의 float 정밀도와 half-up 반올림은 픽셀 경계에서 결과를 바꿉니다. 임의로 단순화하지 마세요.

## 백업과 경로 계약

백업 JSON의 localStorage 값은 문자열로 한 번 더 직렬화되어 있습니다. 코너 순서는 `[TL, TR, BL, BR]`이고 좌표는 0~1로 정규화됩니다.

`worktree.json` v2는 계획 파일 기준 POSIX 상대경로를 저장합니다. 읽을 때 현재 운영체제 경로로 해석하며, v1 절대경로 계획은 기존 경로 우선·이동 위치 폴백을 유지합니다.

## 렌더 순서

```text
원본 읽기
→ 네 모서리 원근 보정
→ 선택적 inset 크롭
→ 수동 색보정
→ 선택적 LED 정리
→ PDF 페이지 저장
```

순서를 바꾸면 화면과 PDF가 달라질 수 있습니다.
